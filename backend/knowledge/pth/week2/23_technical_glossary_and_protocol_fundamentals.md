## 1. Core Technical Terms & Definitions

| Term / Abbreviation | Full Name | Technical Definition & Purpose | Data Format / Type | Library / Standard |
| :--- | :--- | :--- | :--- | :--- |
| **PCM** | Pulse-Code Modulation | Uncompressed raw binary audio format representing analog acoustic sound waves as digital numerical samples over time. Used for sub-second live mic/speaker streaming. | Raw byte array (`byte[]`), 16-bit 16kHz Little-Endian, 32,000 bytes/sec. | Native WebAudio API / AudioWorklet |
| **Base64** | Base-64 Encoding Scheme | Binary-to-text encoding algorithm that converts binary data (PCM audio bytes) into an ASCII text string (using 64 safe printable characters). Required because WebSockets sending JSON cannot embed raw binary bytes without escaping. | ASCII `String` (e.g. `"UklGRiQAAABXQVZFZm10..."`). | `java.util.Base64` / `Base64.getEncoder()` |
| **WSS / WS** | WebSocket Secure | Persistent, full-duplex, bidirectional TCP socket communication protocol (RFC 6455). Allows real-time streaming between browser and Spring Boot server without HTTP polling overhead. | Raw TCP frames (Text frames or Binary frames). | `org.springframework.web.socket.WebSocketSession` |
| **HTTP 101** | Switching Protocols | HTTP response status code sent by Tomcat/Spring MVC to approve the WebSocket handshake, upgrading the connection from HTTP to TCP socket. | HTTP Header `Upgrade: websocket`. | Tomcat WebSocket Container |
| **JSONB** | Binary JSON | High-performance PostgreSQL data type that stores JSON documents in a decomposed binary format, allowing fast indexing and key queries. Used to store form layout blocks. | PostgreSQL `jsonb` column. | Hibernate `@JdbcTypeCode(SqlTypes.JSON)` |
| **pgvector** | PostgreSQL Vector Extension | High-performance open-source vector database extension for PostgreSQL. Stores high-dimensional vector embeddings and computes cosine similarity. | Vector array (`vector(768)`). | PostgreSQL `vector` extension |
| **HNSW** | Hierarchical Navigable Small World | Vector indexing graph structure inside `pgvector` for fast nearest-neighbor semantic vector search. | Index type `USING hnsw (embedding vector_cosine_ops)`. | PostgreSQL `pgvector` HNSW |
| **VAD** | Voice Activity Detection | Algorithm detecting human speech vs silence in audio streams. Used on Next.js frontend to pause sending binary audio frames when candidate is silent. | WASM / WebAssembly Binary (`@ricky0123/vad-web`). | WebAssembly / Web Audio API |
| **BYOK** | Bring Your Own Key | Security pattern allowing workspace creators to supply their own Gemini/OpenAI API keys encrypted with AES-256-GCM in PostgreSQL. | Encrypted String (`String`, 512 bytes). | `javax.crypto.Cipher` (AES-256-GCM) |

## 2. Why Each Concept Is Architecturally Necessary

1. **Why PCM Audio instead of MP3/AAC?**
   - MP3 and AAC require chunk encoding buffer delays (~200ms-500ms). Raw PCM 16-bit 16kHz audio has zero encoding delay, enabling sub-300ms real-time voice latency.
2. **Why Base64 inside JSON WebSockets?**
   - Google Gemini Live API receives setup payloads, tool calls, and media chunks inside JSON text messages (`BidiGenerateContentClientMessage`). Raw binary audio bytes cannot be directly embedded inside a JSON text payload without Base64 string encoding.
3. **Why `pgvector` with HNSW Indexing?**
   - Stores 768-dimensional embeddings generated by `text-embedding-004`. HNSW graph index guarantees sub-5ms cosine similarity lookup across millions of chunks.
